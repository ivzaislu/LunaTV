# Идеи по дальнейшему улучшению

1. **Логирование и наблюдаемость**
   - В `update_playlist.py` и `scaner.py` добавить унифицированный логгер (например, `logging`) с уровнями
     важности и выводом в файл, чтобы легче отслеживать проблемы в проде.
2. **Тесты экстракторов**
   - Расширить набор самотестов для JS-экстракторов и добавить интеграционные проверки, которые прогоняют
     Python-скрипты по локальным HTML-файлам (без сети), чтобы гарантировать совместимость формата данных.
   - Для каждого нового адаптера фиксировать HTML-снимки (например, `ok.ru`, `vk.com`, `1tv.ru`) и
     поддерживать их в `extractor/run-fixture-tests.js`, чтобы регрессии выявлялись заранее.
3. **Устойчивость к сбоям Chromium**
   - Рассмотреть переход на Playwright со встроенным управлением браузером или использовать `puppeteer-extra`
     headless с persistent-контейнером, чтобы снизить вероятность появления «осиротевших» процессов.
4. **Конфигурация**
   - Хранить описания каналов в отдельных файлах (по группам), собирать их при сборке — это упростит
     ведение проекта, особенно при большом количестве каналов.
5. **Библиотека экстракторов**
   - Создать каталог шаблонов для типовых сайтов (например, плейеры на `Video.js`, `hls.js`, защищённые
     смотровые страницы) и описать, какие параметры и куки требуются. Это ускорит добавление новых источников.
6. **CI/CD**
   - Настроить GitHub Actions или другой CI для запуска `npm test` и `python -m compileall` на pull request,
     чтобы сразу ловить синтаксические ошибки и регрессии.
